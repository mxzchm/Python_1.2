======================================================================
7.3. Сумма по строкам/столбцам: C-order vs F-order (3000x3000)
======================================================================
(чистые Python-циклы с arr[i, j], лучшее из 3 — это займёт время...)

Layout       по строкам, с    по столбцам, с
C-order              1.228             1.021
F-order              1.110             0.998

Дополнение: np.sum(axis=...) на тех же массивах (мс, лучшее из 5)
Layout       sum(axis=1)   sum(axis=0)
C-order             5.47          4.79
F-order             5.17          5.41

Дополнение: обход срезами arr[i, :] и arr[:, j] (мс, лучшее из 3)
Layout         arr[i, :]     arr[:, j]
C-order             8.20         14.80
F-order            16.85          8.42

Вывод: в C-order элементы одной строки лежат в памяти подряд, в F-order —
подряд лежат элементы столбца. Обход «вдоль» памяти использует кэш процессора
(cache line = 64 байта = 8 float64), обход «поперёк» — прыгает с шагом n*8 байт
и даёт кэш-промахи. В чистом Python разница мала (порядка шума измерений):
накладные расходы интерпретатора (~сотни нс на arr[i, j]) маскируют
стоимость кэш-промахов.
У np.sum(axis=...) разница тоже небольшая: NumPy сам выбирает порядок
внутренних циклов под layout массива. Зато при явном обходе срезами
arr[i, :] / arr[:, j] выигрыш «правильного» направления заметен
(обычно в 1.5-2 раза) и меняется местами при смене C <-> F.

======================================================================
7.4. (a + b) / (a - b + 1) на 10,000,000 элементах float64
======================================================================
Способ                          время, с   ускорение
Python-цикл + list                1.6242        1.0x
NumPy, одно выражение             0.0722       22.5x
NumPy с out= (буферы)             0.0584       27.8x

Отношение времени «одно выражение» / «с out=» = 1.24 (>1 — вариант с out= быстрее).
Основной выигрыш (десятки раз) даёт сама векторизация. Вариант с out= 
убирает аллокации временных массивов по 80 МБ и page faults, но его 
выигрыш невелик и зависит от машины/аллокатора (от ~0 до ~30%); он 
заметнее, когда выражение вычисляется многократно в цикле.
